System Architecture

Under the hood of the FAQ Whisperer AI. Understanding how natural language is processed and matched.

NLP Text Preprocessing Pipeline

When a user speaks or types a query, it passes through five sequential preprocessing operations before vector calculation occurs. This isolates search intent from grammatical noise:

  • 1. Case Normalization: Conversion of all characters to lower case to make matching case-insensitive.
  • 2. Punctuation Stripping: Standard punctuation symbols are removed to prevent symbol-word attachments.
  • 3. Tokenization: Breaking sentence strings into individual word lists using NLTK's word tokenizer.
  • 4. Stopword Removal: Discarding high-frequency, non-semantic words (e.g., 'the', 'is', 'at') using the NLTK English corpus.
  • 5. Lemmatization: Reducing tokens to their dictionary root representation using NLTK WordNet Lemmatizer.

Similarity Matching Engine

TF-IDF Vectorization

We utilize Term Frequency-Inverse Document Frequency (TF-IDF) from Scikit-Learn to represent our FAQs and queries in a high-dimensional vector space. TF-IDF measures how important a word is in a specific document relative to all documents in the corpus.

Cosine Similarity

Once vectorized, the angle between the query vector and all FAQ vectors is calculated. Cosine similarity calculates the cosine of the angle between two vectors, resulting in a confidence rating between 0% (orthogonal vectors) and 100% (identical directions).

Cosine Similarity Formula
cos(θ) = (A • B) / (||A|| ||B||)

A = Query Vector
B = FAQ Vector

Fuzzy string Fallback

To protect matching accuracy against spelling mistakes, typos, or single-character modifications, our engine blends in a fuzzy matching score computed using Python's standard `difflib.SequenceMatcher` (which implements the Ratcliff-Obershelp gesture pattern matching algorithm). If TF-IDF cosine matching falls short, fuzzy matching ensures users still find what they need.
